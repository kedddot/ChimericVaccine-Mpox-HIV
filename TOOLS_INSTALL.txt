================================================================================
MpoxHIV PIPELINE -- COMPLETE TOOL INSTALLATION
Every external dependency of Phases I, II and III. macOS / Linux, conda-based.
================================================================================

The pipeline uses FOUR conda environments because the tools have mutually
incompatible dependencies (Aggrescan3D is Python 2.7; MHCflurry pins numpy 2.x
while OpenMM/pdbfixer need numpy 1.26). Do not try to merge them.

Scripts locate every binary through an environment variable with a hardcoded
default (see Section 6). If you install anywhere other than the paths below,
export the matching variable instead of editing code.

================================================================================
TOXINPRED2 PATCHES -- REQUIRED, TWO SEPARATE BUGS (added 2026-08-31)
================================================================================
Apply BOTH to every conda env that installs toxinpred2 (toxtools_env is the
one actually used; also apply to phase2's copy if it is ever reinstated --
see the environment note below on why phase2's copy is currently unpatched
upstream on purpose).

---- PATCH 1: 'seqid' NameError on the empty-BLAST branch ----------------
SYMPTOM: crashes with NameError: name 'seqid' is not defined, inside
BLAST_processor(), whenever BLAST returns ZERO toxin hits -- which is the
expected, normal case for this study's candidates. So this fires on every
real run unless patched.
CAUSE: the empty-BLAST branch of BLAST_processor() iterates a local variable
named 'seqid' left over from main(), instead of its own parameter 'name1'.
FIX:
    F=/opt/miniconda3/envs/toxtools_env/lib/python3.11/site-packages/toxinpred2/python_scripts/toxinpred2.py
    cp "$F" "$F.orig"      # if not already backed up
    # in BLAST_processor(), inside the empty-hits branch:
    #     for j in seqid:        -->   for j in name1:
    sed -i '' 's/for j in seqid:/for j in name1:/' "$F"
VERIFY: grep -n "for j in name1:" "$F"   should show 1 match, 0 remaining
"for j in seqid:".

---- PATCH 2: crashes on a batch of EXACTLY ONE sequence ------------------
SYMPTOM: onnxruntime.capi.onnxruntime_pybind11_state.InvalidArgument:
Invalid rank for input: float_input Got: 1 Expected: 2. Fires only when the
input FASTA holds a single sequence (every earlier use in this project
submitted 2+ sequences at once, so this was not caught until Phase 2A's
construct-level check, which submits exactly one sequence -- the whole
assembled vaccine).
CAUSE: in prediction(), `data_test = np.loadtxt(file_name, delimiter=',')`
returns a 1D array for a single-row feature CSV and a 2D array for 2+ rows;
the ONNX model always requires rank 2.
CONFIRMED by direct test: an identical single-sequence input, resubmitted
alongside one padding sequence (n=2), succeeded immediately -- isolating the
failure to n=1 specifically, not a general tool malfunction.
FIX (a no-op when the array is already 2D):
    F=/opt/miniconda3/envs/toxtools_env/lib/python3.11/site-packages/toxinpred2/python_scripts/toxinpred2.py
    cp "$F" "$F.orig"      # if not already backed up
    # in prediction(), immediately after the np.loadtxt line, change:
    #     X_test = data_test
    # to:
    #     X_test = np.atleast_2d(data_test)
    python3 -c "
p = '$F'
s = open(p).read()
old = \"    data_test = np.loadtxt(file_name, delimiter=',')\n    X_test = data_test\"
new = \"    data_test = np.loadtxt(file_name, delimiter=',')\n    X_test = np.atleast_2d(data_test)\"
assert old in s, 'anchor not found -- check the file has not already been patched'
open(p, 'w').write(s.replace(old, new, 1))
"
VERIFY: run toxinpred2 -m 2 on a FASTA holding exactly one sequence and
confirm it completes without the InvalidArgument error.

WHY PHASE2 ENV'S OWN toxinpred2 COPY IS DELIBERATELY LEFT UNPATCHED/UPSTREAM:
